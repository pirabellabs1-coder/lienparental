# Internationalisation (FR / EN / PT) — guide de contribution

Lien Parental est trilingue : **français** (langue source), **anglais** (`en`), **portugais du Brésil** (`pt`).
L'**espace admin reste en français** (outil interne) : ne pas le traduire.

## Architecture

- **next-intl 3**. **Pages publiques** (liste blanche de `lib/i18n/routing.ts` : accueil, aide, blog, Guide,
  pages légales, don, installer, à propos, connexion, inscription) : **une URL par langue**, FR sans préfixe,
  `/en/…`, `/pt/…`, réécrites par `middleware.ts` (après la porte admin et l'anti-CSRF) avec l'en-tête interne
  `x-lp-locale` ; tout autre `/en|pt/…` → 404. **Ailleurs** (espace connecté, API, onboarding…) : **cookie `lp_locale`**.
  Liens internes des pages publiques : `localePath(locale, href)` / `useLocalePath()` ; metadata : `pageMetadata`
  (canonical + hreflang). Sélecteur de drapeaux : `components/i18n/LanguageSwitcher.tsx` (URL de la langue + cookie).
- Résolution par requête : `i18n/request.ts` fusionne
  - le **catalogue cœur** `messages/{locale}.json` (site public, onboarding connexion/inscription, navigation, tableau de bord) ;
  - les **catalogues par module** `messages/{locale}/{module}.json`, chacun sous **sa propre clé racine**
    (ex. `{ "vault": { "list": { … } } }`). Liste : `MODULES` dans `i18n/request.ts`.
- Un module = un propriétaire : on ne modifie **que son fichier** de catalogue (dans les 3 langues).

## Utilisation dans le code

| Contexte | API |
|---|---|
| Composant **serveur** (sans `'use client'`, peut être `async`) | `const t = await getTranslations('vault.list')` (`next-intl/server`) |
| Composant **client** | `const t = useTranslations('vault.list')` (`next-intl`) |
| Locale courante | `useLocale()` (client) / `await getLocale()` (serveur) |
| Dates, nombres, devises | `new Intl.DateTimeFormat(intlLocale(locale), …)` avec `intlLocale` de `@/lib/i18n/config` (fr→fr-FR, en→en-US, pt→pt-BR) |

| **Bibliothèque** `lib/*` sans hook (synchrone, surtout côté navigateur) | `libT('shared.vault')('errors.tooBig')` de `@/lib/i18n/runtime` — catalogues `auth` et `shared` uniquement ; langue = `<html lang>` (français côté serveur) |
| Code **serveur asynchrone** pendant une requête (route API, Server Action) | `const t = await getTranslations('server.vault')` (suit le cookie de l'utilisateur) |
| **Hors requête** (cron, e-mails, notifications) | `createTranslator({ locale, messages })` avec la langue du **destinataire** (`preferences.langue`) |

Règles :
- **Pas de `t()` au niveau module** (les hooks ne vivent que dans les composants). Les tableaux/maps de libellés
  définis hors composant deviennent des **clés**, traduites au rendu : `t(\`types.${type}\`)`.
- Un composant sans `'use client'` rendu **par un composant client** est un composant client : utiliser `useTranslations`
  (ajouter `'use client'` seulement s'il n'importe rien de `server-only`).
- **Ne pas masquer `t`** : un `items.map((t) => …)` dans un composant qui utilise `t` pour les traductions → renommer la variable.
- Interpolation ICU : `"Bonjour {name}"`, pluriels `"{count, plural, one {# document} other {# documents}}"`.
- Traduire aussi l'**accessibilité** : `aria-label`, `sr-only`, `alt`, `title`, `placeholder`.
- Fichiers `lib/*` **partagés** : ne pas changer leur comportement pour les autres. Préférer traduire au rendu.
  Ajouts **additifs** seulement (ex. un champ `key` optionnel), jamais de valeur existante modifiée.
- Ne pas toucher : **e-mails**, logique **facturation/auth/middleware/base**, messages d'erreur des **routes API**.

## Pièges connus

- Le français utilise des **espaces insécables** avant `? ! :` : une édition « chercher/remplacer » exacte peut échouer.
  Relire le fichier et copier le texte exact, ou réécrire un bloc plus large.
- **Ne jamais lancer `next build` pendant que `next dev` tourne** : ils partagent `.next` et corrompent le serveur de dev.
